Install

SQL files in. A pipeline out.

Number your SQL files, run one command, and qdata runs them as a pipeline on an embedded DuckDB engine. Every step is logged and cached, so after a fix you replay from that step instead of from scratch. It fetches and crawls websites too, and you parse the pages with XPath in plain SQL. No Airflow, no Python environment, no server.

$curl -fsSL https://cuiqanalytics.github.io/qdata/install.sh | sh
$docker pull ghcr.io/cuiqanalytics/qdata

Free, with no pipeline or row limits on runs. No account, no telemetry. Works offline.

From download to first pipeline in under a minute

qdata demo creates a sample project you can run straight away.

A folder of SQL files is a pipeline

Each file creates a table, and the next file reads it. The numbers set the order. The file name sets the role: ingest, validate and export are recognised, and everything else is a transform.

A validate step is a query that returns the bad rows. If it returns any, the run stops before bad data reaches your export.

│   └── 003_export.sql     COPY transform TO '../output/results.csv'

Scrape a site with XPath in SQL

A scrape step fetches pages into a table, one row per URL with its status and HTML. It can enumerate {page} numbers, follow "next" links or start from a SQL query. It reads robots.txt, rate-limits each host, retries 429 and 5xx responses, and caches pages between runs.

Then you extract with the webbed DuckDB extension, which ships with qdata. One XPath per column and unnest gives you one row per match.

Server-rendered HTML only: qdata does not run JavaScript. Fetching a single page with an ingest step is free; crawling many pages is a Pro feature.

[[steps]]
name = "crawl"
type = "scrape"
output_table = "raw_pages"
urls = ["https://books.toscrape.com/catalogue/page-1.html"]
follow = { xpath = "//li[@class='next']/a/@href", max_depth = 4 }
rate_limit = "2/s"
cache = "12h"

[[steps]]
name = "extract"
type = "transform"
output_table = "books"
query = """
CREATE OR REPLACE TABLE books AS
SELECT unnest(xpath_all(body, '//article/h3/a/@title')) AS title,
       unnest(xpath_all(body, '//p[@class="price_color"]')) AS price
FROM raw_pages WHERE status = 200
"""

What comes with every run

Replay from any step

Pass --cache cache.db and step outputs are kept. Fix step 4 and run with --start-step 4; steps 1 to 3 aren't recomputed.

A log of every run

Each run, step, row count, duration and output hash goes into a local SQLite log. qdata report turns it into an HTML page.

Dry runs

--dry-run --preview 5 runs every query and shows the first rows of each step, without writing any exports.

Dates and variables

{{YYYYMMDD}}, {{date_sub(YYYYMMDD, 7)}} and environment variables work in paths and SQL, so a daily export names itself.

Files and databases

Read and write CSV, Parquet, JSON and Excel. Ingest from or sink to MySQL and PostgreSQL with a connection URI.

Offline by default

DuckDB and its extensions ship in the download, so a pipeline over local files never touches the network.

Questions

Does it need internet access or an account?

No. It's one download with DuckDB and its extensions inside, and Pro licenses are verified offline. It only goes online when your pipeline fetches a URL. No telemetry.

Does it run on macOS and Windows?

The native binary is for Linux (x86-64). On macOS and Windows, use the Docker image: docker pull ghcr.io/cuiqanalytics/qdata. On Apple Silicon, add --platform linux/amd64.

Can it scrape sites that load content with JavaScript?

No. qdata reads the HTML the server sends. Many such sites load their data from a JSON API, which you can see in your browser's network tab. Point an ingest step at that URL and it loads as a table.

Is scraping with it polite?

By default, yes: the crawler obeys robots.txt (including Crawl-delay), limits requests per host, and sends the user agent you set. Checking a site's terms of use is still up to you.

How is this different from dbt or Airflow?

There's no project framework to learn and no scheduler service to run. A pipeline is a folder of SQL files that runs on your laptop or a single server. When you need a schedule, Pro adds one in the same binary.

What happens if my Pro license lapses?

Pro features stop. Everything in the free tier keeps working, and your pipelines and outputs are untouched.

Can an AI assistant use qdata?

Yes. Install the Claude Code skill and describe the pipeline you want. Claude writes the SQL or TOML, runs it and checks the output.
